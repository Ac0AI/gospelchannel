## Why this matters

`pnpm audit --prod` reports two cache-poisoning advisories against the installed `next@16.1.6` (GHSA-3g8h-86w9-wvmq, GHSA-vfv6-92ff-j949), both patched in `>=16.2.5`; the latest 16.x at planning time is 16.2.9. Separately, the audit total (85 findings, 1 critical, 36 high) is dominated by packages that are only used by local maintenance scripts but live in production `dependencies` — they don't ship to the Worker (the bundler tree-shakes by import), but they make every audit unreadable and confuse contributors about what the site actually runs on. This plan patches Next and reclassifies script-only packages so the production audit reflects reality.

## Steps

### Step 1: Bump Next.js

In `package.json` set `"next": "16.2.9"` and `"eslint-config-next": "16.2.9"`, then run `pnpm install`.
(If 16.2.9 no longer exists or a newer 16.2.x is current, use the latest 16.2.x — check with `pnpm info next versions --json | tail -5`. Never jump to a 17.x.)

**Verify**: `pnpm install` → exit 0; `pnpm exec tsc --noEmit` → exit 0.

### Step 2: Re-verify each demotion candidate, then move it

For each of `@supabase/supabase-js`, `apify-client`, `@mendable/firecrawl-js`, `@sindresorhus/is`, `@anthropic-ai/sdk`, `@better-auth/cli`:

1. Run `grep -rln "<package-name>" src/ worker.ts open-next.config.ts next.config.ts`.
2. If zero matches → move the entry from `dependencies` to `devDependencies` in `package.json` (keep its version specifier unchanged).
3. If ANY match → leave it in `dependencies` and record the file path in your report.

Then run `pnpm install` once after all moves.

**Verify**: `pnpm install` → exit 0; `git diff package.json` shows only version bump (step 1) + block moves, no removals.

### Step 3: Full verification sweep

Run in order: `pnpm lint`, `pnpm exec vitest run`, `pnpm build`, `pnpm cf:build`.

**Verify**: every command exits 0. For `pnpm build`/`pnpm cf:build`, treat warnings as OK, errors as failure.

### Step 4: Record the audit delta

Run `pnpm audit --prod | tail -3` and include the before/after severity summary in your report (before, at planning time: `85 vulnerabilities found — Severity: 4 low | 44 moderate | 36 high | 1 critical`). The two `next` advisories (GHSA-3g8h-86w9-wvmq, GHSA-vfv6-92ff-j949) must be gone: `pnpm audit --prod 2>/dev/null | grep -c "GHSA-3g8h-86w9-wvmq\|GHSA-vfv6-92ff-j949"` → `0`.
